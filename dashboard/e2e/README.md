# P15 화면 로컬 검증

## 실행

`dashboard` 폴더에서 실행한다. 새 패키지 설치는 필요 없다. 기존 의존성과 Playwright 브라우저를 사용한다.

```sh
npm test
npm run build
LIVEPROBE_MOCK=1 npx playwright test
```

마지막 명령은 `127.0.0.1:8015`의 모의 API와 `127.0.0.1:4175`의 빌드 미리보기를 자동으로 열고, 시험 후 종료한다. 포트가 이미 사용 중이면 실패하며 다른 서버를 재사용하지 않는다. 모의 시험에서는 `LIVEPROBE_URL`을 무시하고 이 로컬 미리보기만 사용한다.

수동 탐색은 터미널 두 개에서 실행한다.

```sh
node e2e/mock-api.mjs
LIVEPROBE_MOCK_API=http://127.0.0.1:8015 npm run preview -- --host 127.0.0.1 --port 4175 --strictPort
```

실제 배포 후 읽기 전용 구조 시험:

```sh
LIVEPROBE_URL=http://liveprobe.localhost npx playwright test e2e/p15-overview.spec.mjs e2e/p15-incident-room.spec.mjs
```

실제 배포 주소에서 명령·제어·비밀값 시험은 실행하지 않는다. `p15-commands.mock.spec.mjs`·`p15-states.mock.spec.mjs`·`p15-review5.mock.spec.mjs`·`p15-review3.mock.spec.mjs`는 `LIVEPROBE_MOCK=1`이 아니면 건너뛴다. `model-settings.spec.mjs`의 저장 시험은 브라우저 경로를 가로채고 클러스터 설정을 변경하지 않는다.

## 기반 이미지 다운로드가 막힌 경우의 로컬 대체 빌드

프로젝트 루트에서 `python3 scripts/build-dashboard-assets.py --tag <새 태그> --output <결과 JSON 절대경로>`를 실행한다. 먼저 위 단위·빌드·모의 시험을 통과해야 한다. 스크립트는 고정된 p15o의 로컬 런타임을 실행 없이 export하고 이전 화면만 제외한 rootfs와 dist로 새 이미지를 만든다. 로컬 base가 없거나 기존 태그가 있으면 중단하며 외부 다운로드는 하지 않는다. 원격 기반 이미지와 npm 설치까지 다시 검증하는 클린 빌드가 아니므로 결과 JSON의 base·asset 해시와 실제 배포 번들 일치를 별도로 기록한다.

## 표본 출처와 한계

`~/.hermes/cache/scratch/p15-samples`의 읽기 전용 수집 표본에서 변환했다. 원본 표본을 저장소에 추가하거나 클러스터에 요청을 보내지 않고 실행할 수 있다.

| 화면 표본 | 원천 | 표현하는 경로 |
| --- | --- | --- |
| `narrative-971.json` | `incident-971.json`, `events-971.json` | 복잡 그룹, 모델 승격, 병렬 반론·복구 계획, 메모리 한도 변경·자동 복구 |
| `narrative-987.json` | `incident-987.json`, `events-987.json` | 단순 그룹, 이미지 오류, 이전 배포로 롤백 |
| `narrative-990.json` | `incident-990.json`, `events-990.json` | 고위험, 근거·안전 검증 후 인계 |
| `narrative-976.json` | `incident-976.json`, `events-976.json` | 보통 그룹의 병렬 로그·쿠버네티스 분석 |
| `narrative-1976.json` | 976의 초기 실행 기록 | 진행 중 상황을 위한 로컬 재구성. 실제 장애 번호가 아니다. 실행 중·예정 노드를 포함한다. |
| `overview.json`, `topology.json` | 실제 토폴로지, 지표·이벤트 표본 | 로컬 진행 장애 핀과 서비스·포트·엔드포인트. 읽기 쉽게 두 네임스페이스로 한정했다. |
| `command-plans.json` | 로컬 시험용 작성 | 수량 조정, 클러스터 범위 노드 배치 차단, 비밀키 변경 |

로그와 이벤트 메시지는 실제 표본 문자열을 보존했다. 에이전트 결론 원문도 실제 표본이다. 한글 결론·상황 요약은 화면 시험을 위해 작성한 해석이며 실제 해석 모델 실행 결과라는 뜻이 아니다. `ko_source`는 계약상의 표시 상태를 시험하기 위한 값이다. 관측되지 않은 CPU·메모리 사용량·상위 95% 지연·재시작 증분은 `null`이다. 누적 재시작을 최근 1시간 증분으로 오인하지 않는다. 준비 상태는 실제 토폴로지, 요청·오류 지표는 수집 표본에서 가져왔다. 오늘의 처리 건수는 이 로컬 사례 묶음의 요약이며 실제 클러스터의 오늘 집계가 아니다.

재생성:

```sh
python3 e2e/build-fixtures.py ~/.hermes/cache/scratch/p15-samples
```

실행 중 사례와 지시 상태 전이는 화면 검증을 위한 구성이다. 모의 서버는 Kubernetes·DB·LLM·외부 서비스에 접속하지 않는다. 비밀값은 존재 여부만 검사하고 본문 참조를 버린다. 값은 서버 상태·이벤트·응답·로그에 넣지 않는다. 이 시험은 실제 백엔드의 값 비저장 보안 검증을 대신하지 않는다.

## 검사 범위

- 375×844 / 768×1000 / 1440×1000에서 같은 구조 시험을 실행한다.
- 전체 운영 관제, 정상 자원 상세, 장애 핀 진입, 제거 주소 이동, 검토 기록·설정 경로.
- API로 사례를 고른다. 장애 ID·요약 문구를 실서비스 시험에 고정하지 않는다.
- 원문 문자열 보존, 한글 해석, 필터, 선택 역할 상세, 입력 근거 강조·이동, 대화 접근.
- 원문·흐름·대화 탭, 필터, 실제 흐름 노드 버튼, 확인 버튼을 키보드로 조작한다.
- 지시 생성 → 계획 → 사전 검사 변경 내역 → 부작용 확인 → 진행 → 검증 결과 → 원복.
- 클러스터 전체 영향 경고와 취소, 실패한 사전 검사·누락 부작용의 진행 차단, 계획 해시 409.
- 비밀키별 `type=password`, `autocomplete=off`, 전송 직후 초기화, DOM 텍스트·웹 저장소·모의 이벤트·응답의 표식 값 부재.
- 분석 중 지시 해석, 일시정지·재개, 메시지 409 경합 후 지시 생성.
- 기존 자동 조치 승인·거절 확인(취소 시 전송 없음), 인계 인수, 필터 변경 후 이전 주기 조회의 늦은 응답 폐기. 모의 API 상태 전이이며 실제 엔진 실행 증거는 아니다.
- 빈 데이터·미관측·해석 대기·첫 조회 오류와 재시도.
- 문서 및 보이는 측면 영역의 가로 넘침, 제어 사각형 겹침, 한국어 버튼 내부 잘림, 텍스트 색 대비.

기존 Kiali·구형 지도·우측 라우팅 표 전용 시험은 새 운영 관제와 관제실 시험으로 대체했다. 모델 설정 회귀 시험은 유지하며 좁은 메뉴의 지도 문구만 관제로 갱신했다.

## 증거 파일

- `artifacts/mock/*.png`: 모의 API + 실제 빌드 미리보기 캡처. `artifacts/live/*.png`: 실배포(`liveprobe.localhost`) 읽기 전용 캡처. 명령 확인·비밀값 화면은 관련 버튼을 보이는 위치로 이동한 뒤 캡처한다.
- `artifacts/captures.jsonl`: 경로·화면 상태·뷰포트·실제 주소·시각·화면 소스 해시.
- `artifacts/layout.jsonl`: 문서와 영역의 폭, 제어 겹침, 컨트롤 잘림의 실제 측정.
- `artifacts/npm-test.log`, `npm-build.log`, `playwright.log`(모의), `playwright-live.log`(실배포 읽기 전용): 마지막 검증 출력.
- `artifacts/manifest.json`: 현재 소스 해시 기준의 시험 수·배치 측정·캡처 목록. 다른 해시의 기록은 제외한다.
- `P15-report.md`: 완료 범위·검증 수·직접 이미지 검토·계약 확인 요청·미수행 사항.

자동 측정 통과를 전면 접근성 인증이나 실제 클러스터 검증으로 표현하지 않는다. 배포·실제 장애 재현은 이 작업에 포함하지 않는다.
