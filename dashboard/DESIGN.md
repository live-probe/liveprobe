## P18 통합 관제실 추가 계약 (인터뷰 반영·아직 미구현)

이 절과 `docs/plans/revamp/P18-incident-conversation-brief.md`는 아래 P15/P16의 관제실3열·단계 선택 시 근거 탭 이동 규칙을 대체한다. 아래 내용은 기존 구현의 계약 이력이며, 새 관제실을 구현·검증했다고 주장하지 않는다.

- 기본은01 AI 분석 흐름 +02 분석·운영자 통합 채팅의2영역이다. 개요·한글 결론·단계 고유 내용은 채팅 카드에 기본 표시한다.
- 흐름 노드 선택은 정확한 실행 카드로 채팅 내부를 부드럽게 이동하고 잠시 강조한다. 단계 선택만으로 상세 패널을 열지 않는다. 재시도·상위모델 실행은 역할명 대신 실행ID로 구별한다.
- 카드 상세보기 때만 기존03과 동급 폭의 오른쪽 패널을 연다(기존1440px 화면 측정340px, 다른 폭은 반응형). 닫기/Esc 후 기본2영역으로 복귀하며 작성 초안·채팅 위치·포커스를 보존한다.
- 수집9건이면 실제9개 항목의 짧은 정보·출처·상태를 읽을 수 있어야 한다. 분석 카드에는 관측·원인·결론, 검증 카드에는 검증 대상·수락/반려·확인 결과를 보이며 같은 근거 목록 반복으로 대체하지 않는다.
-02의 입력란·분석 제어와 승인/인계/종료/PR·승격 카드를 유지한다. 원문·긴diff·기술정보는 상세로 분리하고 승인·비밀값 안전 경계는 바꾸지 않는다.
- 기존 흑연 흐름 토큰과 밝은 대화 표면을 유지한다. 새 카드의 한글 개요·결론은14px 이상, 어절 줄바꿈·제목/상태/결론 위계로 구분하고 균일한 장식 카드 반복을 피한다.
- 네이티브 스크롤·CSS 강조를 우선하고 움직임 감소 설정에서는 즉시 이동한다. 실시간 갱신이 과거 대화를 읽는 운영자의 위치를 빼앗지 않는다. 새 스크롤 라이브러리는 추가하지 않는다.
- 모바일은 흐름/대화 두 전환과 전체 폭 상세 서랍을 권장 기본값으로 한다. 새 화면 수용 기준은U1~U8이며1440/768/375px 캡처·키보드·모션·입력/승인 회귀를 별도 확인한다.

## P16 다이어그램 시각 계약

기본 방향은 **정밀한 운영 콘솔**이다. 두 다이어그램만 짙은 흑연색 작업면으로 분리하고 기존 밝은 메뉴·근거·대화 영역은 유지한다. 장식성 그라디언트·유리 효과·대형 제목·새 라이브러리는 추가하지 않는다. Linear의 명도 단계·절제된 테두리와 로컬 디자인 자료의 Slate Console을 참고하되 브랜드·서체를 복제하지 않는다. 기존 흰 카드의 균일한 녹색 테두리, 의미 없는 문자 아이콘, 작은 원천 수치의 반복을 개선한다.

- 배경 `#0c1420`, 네임스페이스 표면 `#111d2d`, 노드 `#19283b`, 선택 노드 `#213452`, 경계 `#34465f`, 점 격자 `#28384d`.
- 본문 `#edf3fc`, 보조 `#b7c6d9`, 메타 `#a0b2ca`, 선택·실행 `#a9baff`, 완료 `#85dfb5`, 승격·경고 `#ffd08a`, 실패 `#ff9da7`, 재배치 `#d0b1ff`. 밝은 화면의 기존 토큰은 유지한다. 새 색은 다이어그램 범위에만 적용한다. 텍스트 대비 4.5:1 이상.
- 한국어 글꼴은 기존 시스템 스택, 수치·모델 식별자는 기존 고정폭 스택. 다이어그램 주요 제목 14–15px, 설명 14px, 수치 메타 12px 이상(확대 전 좌표 기준). 축소 전체 보기에서는 확대 제어로 원래 크기를 읽을 수 있게 한다. 모델·긴 이름은 상세와 접근 이름에 원문을 보존한다.
- 서명 요소: 역할별 선형 SVG 아이콘, 단계 번호와 실행 상태의 분리, 네임스페이스 상단의 자원 수·문제 수, 실측 연결의 두께·상태와 미관측 점선. 모든 상태는 색과 문구를 함께 사용한다. 완료 단계 전체를 녹색 상자로 채우지 않는다.
- 간격 4/8/12/16/24px, 노드 반경 10px, 묶음 반경 14px, 미세한 노드 그림자만 허용한다. 선택은 밝은 테두리+외곽선, 키보드 포커스는 별도 3px 외곽선이다. 호버는 경계 밝기만 바꾸며 노드 위치는 움직이지 않는다.
- 서비스 지도: 전체 자원/네임스페이스/실측 연결 개수의 짧은 요약, 기존 필터·전체 보기·장애 진입·모든 상세 수치를 유지한다. 신규 건강 점수·가상 트래픽은 만들지 않는다. 미관측은 정상으로 표현하지 않는다.
- 실시간 연결 관측으로 같은 자원 수에서도 열·행·묶음 배치가 달라질 수 있다. 자원 개수가 아니라 실제 노드/묶음의 식별자·위치·크기가 바뀔 때 전체 맞춤을 다시 수행한다. 수치만 갱신되면 운영자의 확대·이동은 유지한다.
- AI 흐름: 위→아래 depth·좌→우 lane·병렬·승격·운영자 지시 경로를 유지한다. 종류 아이콘과 작은 단계 번호로 경로를 읽고 상태 배지는 별도 표시한다. 단계 선택·결론·근거 이동은 기존 API 그대로다. 전체 맞춤의 최소 읽기 배율 정책을 유지한다.
- 범례와 확대 제어는 캔버스 아래 독립 행이다. 1440/768/375px에서 제어가 노드를 가리지 않고 페이지·패널 가로 넘침이 없어야 한다. 빈 흐름·미관측 지도·오류·지연 경고에도 동일한 시각 위계를 유지한다.
- 움직임은 실행 중 연결만 사용하며 기존 움직임 감소 설정에서 끈다. 배경의 가짜 실시간 점멸·무의미한 맥동은 추가하지 않는다.
- 성능 예산: 로컬 Chromium 1440×900, 네트워크·CPU 제한 없는 새 페이지의 `/`·`/incidents/1019`에서 실험실 LCP 2.5초 미만. 구현 전 동일 조건 기준선을 기록한다. 실제 사용자 p75·INP 통과 주장으로 확대하지 않는다.
- 변경 범위: 두 다이어그램·공유 확대 제어·전용 스타일·회귀시험·대시보드 배포. 백엔드·실행 권한·인증·클러스터 자원 구성·평가 화면·Jira·커밋·push는 제외한다. 아래 P15 동작 계약은 이 절에서 변경한 시각 규칙 외에는 유지한다.

## 목적과 화면 구조

첫 화면은 클러스터 전체의 **운영 관제**다. 주인공은 **서비스 연결 지도**다. 지도에서 장애 위치를 찾고, 장애 자원을 누르면 그 장애의 **장애 관제실**로 이동한다. 장애 관제실은 단순한 인계 배지가 아니라 AI가 거친 단계를 위에서 아래로 보여 주고, 각 단계의 한글 결론과 근거, 운영자가 할 다음 일을 드러낸다.

- `/`: 서비스 연결 지도(왼쪽 전체) + 클러스터 상태 보조 영역(오른쪽).
- `/incidents`: 검색·상태 필터·현재 AI 단계가 있는 장애 목록.
- `/incidents/:id`: 한글 상황 요약 + 세로 분석 흐름 / 단계·근거 / 운영자 대화.
- `/ledger`, `/settings`: 검토 기록과 버전형 모델 설정을 유지한다.
- `/map`: `/`로 이동한다. Kiali 삽입 화면과 이전 자원 지도는 사용하지 않는다.
- 메뉴: 운영 관제 / 장애 관제 / 검토 기록 / 설정. 작은 화면: 관제 / 장애 / 검토 / 설정.
- 상단 바: 왼쪽은 현재 위치(예: 장애 관제 / 장애 #971), 오른쪽은 분석 계정 상태와 **진행 중 장애 알림 버튼**이다.

## 시각 원칙

밝은 상용 관측 콘솔의 정보 밀도와 위계를 따른다. 흰 작업 표면, 옅은 회색 배경, 얇은 구분선, 작은 상태 색을 사용한다. 장식형 히어로·그라디언트·웹 폰트·차트 라이브러리는 추가하지 않는다. 화면 제목만 있는 머리 영역은 두지 않는다(보조 기술용 제목은 유지한다). 수치는 원천 값이며 임의의 건강 점수를 만들지 않는다.

색 토큰은 `styles.css`가 기준이다.

| 역할 | 전경 | 배경 |
| --- | --- | --- |
| 본문 | `#172337` | `#ffffff` |
| 보조 설명 | `#526174` | `#ffffff` |
| 메타 정보 | `#607086` | `#ffffff` |
| 선택·포커스 | `#245bb5` | `#edf3ff` |
| 준비·완료 | `#126840` | `#eaf6ef` |
| 경고·인계 | `#934807` | `#fff3e2` |
| 오류·장애 핀 | `#b4232c` | `#fff0f1` |

본문과 상태 텍스트는 해당 바탕에서 명도 대비 4.5:1 이상을 확보한다. 색만으로 구별하지 않고 상태 문구와 경계선 형태를 함께 사용한다. 포커스는 3px 외곽선이다.

한국어 시스템 글꼴 스택을 유지한다: `-apple-system`, `BlinkMacSystemFont`, `Pretendard`, `Apple SD Gothic Neo`, `Noto Sans KR`, `Malgun Gothic`, `Segoe UI`, `sans-serif`. 외부 글꼴을 내려받지 않는다. 일반 본문 14px, 한글 해석 13px, 관제실 설명 12px, 조밀한 메타 10–11px다. 원문·모델 ID·근거 ID는 시스템 고정폭 글꼴을 사용한다. 한국어는 어절 단위 줄바꿈을 우선하되 긴 이름과 원문은 영역 안에서 줄바꿈한다. 흐름 노드의 둘째 줄(종류·모델·내용)만 한 줄 말줄임을 허용하며, 전체 문구는 접근 이름과 단계 상세에 남긴다.

간격은 4/8/12/16/18/24px, 모서리는 4/6/8/10px다. 그림자는 지도 자원, 흐름 노드, 알림 드롭다운에만 작게 사용한다.

## 스크롤 정책

데스크톱(1100px 초과)에서는 **페이지 자체가 세로로 스크롤되지 않는다**. 남는 스크롤은 아래 네 가지뿐이며 각각 목적이 있다.

1. 장애 관제실 가운데 열: 근거 묶음과 선택 단계 상세 열람.
2. 장애 관제실 오른쪽 열: 대화·실행 기록·지시 카드 열람. 입력란은 열 하단에 고정된다.
3. 운영 관제 보조 영역의 탭 내용: 경고 이벤트 / 네임스페이스 / 자원 상세.
4. 알림 드롭다운의 장애 목록(장애가 많을 때만).

지도와 흐름은 스크롤 대신 확대·축소·전체 보기와 끌어 이동을 사용한다. 1100px 이하에서는 탭 전환과 세로 쌓기를 허용하고, 운영 관제는 지도(화면 높이의 약 2/3) 아래에 보조 영역을 둔다.

## 운영 관제

**지도**가 왼쪽 전체 높이를 차지한다. 도구 줄에는 제목, 네임스페이스 선택, 자원 선택(지도에서 숨긴 자원 포함), 시스템 구성요소 표시 전환, 자원 수가 있다. 처음 열거나 보이는 자원 구성이 바뀌거나 캔버스 크기가 바뀌면 **전체 지도를 화면에 맞춘다**. 일반 10초 갱신은 운영자가 옮긴 시점을 유지한다.

- 네임스페이스 경계 안에 진입 → 서비스 → 저장소 계층을 배치한다. 각 네임스페이스 상자는 **실제로 쓰는 열만** 차지하고, 상자들은 화면 비율(가로 1.25:1)에 가깝게 여러 줄로 배치한다.
- **시스템 구성요소**(kube-system, kube-public, kube-node-lease, liveprobe-observability, istio-system, default/kubernetes, system·job 역할)는 기본으로 숨긴다. 문제나 열린 장애가 있는 구성요소는 숨기지 않는다. "시스템 구성요소 N개 표시"로 모두 보이고, 특정 네임스페이스를 고르면 그 안의 자원을 모두 보인다. 숨김은 화면 정리일 뿐이며 자원 선택 목록에는 "지도에서 숨김"으로 남는다.
- 접힌 Service의 이름·포트·준비된 엔드포인트 수를 상세에 보존한다. 엔드포인트가 0개인 Service는 '엔드포인트 없음' 경고이며 시스템 네임스페이스여도 숨기지 않는다. 간선은 상대 노드와 마주 보는 면에 붙인다. 선 위 숫자는 관측된 요청률이 있으면 `초당 요청 · 오류율`(API 0~1 비율을 화면에서만 %로), 없으면 흐름 이벤트 수다. 숫자는 **같은 네임스페이스의 이웃한 열·행 사이 빈 칸**에서만 그린다. 자원을 건너뛰거나 네임스페이스를 넘거나 양방향인 연결의 숫자는 자원 카드·다른 숫자에 가려지므로 선 위에 그리지 않고, 자원 상세의 '연결' 목록에 방향·상대·수치로 모두 보존한다. 접근 이름에는 항상 수치를 넣는다. 미관측 구조 연결은 점선, 지연된 관측은 흐리게 표시한다.
- 장애가 없어도 관측 경고(통신 오류·차단, 엔드포인트 없음 등)가 있는 자원은 주황 경계와 '관측 경고' 문구로 정상과 구분하고, 상세에 원천 근거를 보인다.
- 장애 자원에는 수준이 적힌 맥동 핀을 붙인다. 장애 자원 선택은 장애 관제실로, 정상 자원 선택은 보조 영역의 자원 상세로 연결된다. 키보드 포커스가 화면 밖 자원에 닿으면 확대 비율을 유지한 채 그 자원으로 이동한다.
- 확대·축소·전체 보기와 범례는 캔버스 아래 별도 행에 있어 노드를 가리지 않는다.

**보조 영역**(오른쪽 320px)은 위에서부터 다음과 같다.

1. 클러스터 상태 제목, 관측 기준 시각, 새로고침.
2. 원천 상태(Kubernetes / Prometheus / Hubble / Envoy): 연결됨 / 확인 필요 / 미관측, 오류 원문 펼치기.
3. 압축 요약: 준비 노드, CPU·메모리 사용/용량(막대), Pod 실행·대기·실패, 최근 1시간 재시작, 진행 중 장애(수준별), 오늘 자동 복구·인계·실패·감지.
4. 탭: 경고 이벤트(한글 사유 제목 + 원문 사유·메시지 그대로) / 네임스페이스별 자원 / 자원 상세(선택 시).

**숫자 `null`은 미관측이다.** 0으로 치환하지 않는다. 합계에 누락된 값이 있으면 부분 합계를 전체처럼 표시하지 않는다. 녹색 준비 점은 수집된 자원 준비 상태만 뜻한다. 전체 관제는 10초마다 갱신한다.

**진행 중 장애**는 지도 옆 고정 목록이 아니라 상단 바 오른쪽 알림 버튼(`진행 중 장애 N건`)에 있다. 버튼은 모든 화면에 있다. 목록은 최근 기록 개수와 무관하게 진행 상태(open·analyzing·action_pending·acting)별 전체 페이지를 조회한다. 일부라도 조회에 실패하면 0건으로 표시하지 않고 `?`와 마지막 조회 목록·실패 안내를 보인다. 누르면 수준 높은 순으로 장애·네임스페이스·상태·경과 시간을 보여 주는 드롭다운이 열린다. 항목을 고르면 장애 관제실로 이동한다. Esc 키(포커스는 버튼으로 복귀)와 바깥 클릭으로 닫힌다. 진행 중 장애가 있으면 버튼이 적색으로 강조된다.

## 장애 관제실

맨 위 **상황 요약**은 한 줄 머리말(목록으로, 번호, 수준, 상태, 경과 시간, 해석 포함 추정 비용), 한글 제목, 영향, 현재 단계와 다음 할 일이다.

데스크톱은 아래 3열이다.

1. **AI 분석 흐름(세로)**: 서버의 `depth`를 세로(위→아래), `lane`을 가로로 사용한다. 신호 → 근거 → 분류 → 그룹 → 병렬 에이전트 → 검증 → 조치 → 결과, 지시·명령·해석 노드를 그대로 그린다. 노드는 두 줄이다: 한글 역할명(또는 단계 이름)과 짧은 상태 / 종류·모델(또는 내용). 처음과 새 단계 추가, 캔버스 크기 변경 때 **흐름 전체를 맞춘다**. 맞춘 결과가 읽기 어려운 배율(0.6 미만)이면 0.6으로 위쪽부터 보여 주고 끌어 이동하게 한다. 예정은 회색 점선, 실행 중은 파란 강조, 완료는 녹색 경계, 실패는 적색, 승격은 주황색, 경로 변경은 보라색 점선, 지시 반영은 파란 점선, 검증은 녹색 선이다. 같은 줄의 병렬 연결은 문구 없이 색·선 모양과 접근 이름으로 구분한다. 노드 버튼이 키보드 진입점이다(별도 단계 목록 없음).
2. **근거 · 한글 해석 / 선택한 단계 · 근거**: 원문은 **같은 종류·출처·한글 해석끼리 한 묶음**으로 보인다. 묶음마다 심각도·출처·건수·시각 범위, **한글 해석이 먼저**, 그 아래 **"영어 원문 보기(N건)"**를 펼치면 원문 전체가 문자열 그대로 나온다. 해석이 없는 원문은 묶지 않는다. 필터(전체/오류/이벤트/로그/상태/에이전트)를 제공한다. 흐름에서 단계를 고르면 그 단계가 인용한 원문만 먼저 걸러 낸 뒤 묶는다(같은 해석이라도 인용하지 않은 원문은 섞지 않는다). 이 열이 **선택 단계 상세**(한글 역할·맡은 일, 상태, 한글 결론, 결론 원문 펼치기, 모델·추론 강도·토큰·비용·시간, 입력 근거 버튼) + **그 단계가 본 근거 묶음만**으로 바뀐다. 입력 근거 버튼은 해당 묶음을 강조하고 원문을 펼친 채 가운데로 이동한다. 응답에 없는 근거는 "원문 없음"으로 표시한다. 인용 역할 버튼은 그 단계를 선택한다.
3. **운영자 대화(상시 표시)**: 운영자 메시지, AI의 지시 해석·대상 역할·적용 시점, 실행 기록(한글 제목, 원문 펼치기), 지시 확인 카드를 구분한다. 기존 엔진 자동 조치의 승인·거절과 운영자 인계 인수도 별도 카드로 유지한다. 자동 조치는 대상·요청 변경 값을 먼저 보이고 전체 매개변수·스냅샷 원문은 접어 둔다. 승인·거절에는 명시 확인이 필요하며 서버가 정책·안전 검사를 다시 수행한다. 인계 인수는 담당 기록일 뿐 변경 허가가 아니다. 진행 중에는 일시정지 / 재개 / 중단을 유지한다.

1100px 이하는 상황 요약 + `흐름 / 근거·해석(단계 선택 시 단계·근거) / 대화` 전환 버튼이다. 버튼은 `aria-pressed`를 갖는다. 단계를 고르면 근거 탭으로 이동한다. 확인 대기 중인 지시가 있으면 대화 버튼에 표시가 붙는다. 긴 상황 요약만 제한된 높이에서 따로 스크롤한다.

운영 상태는 사건 상세와 해석 응답 중 `updated_at`이 더 최신인 사건 스냅샷을 사용하고 같은 시각이면 상세를 우선한다. 상태가 같을 때만 상세의 인수 정보를 보존하며 오래된 인계 정보를 다른 상태에 붙이지 않는다. 인계 카드·메시지 전송 경로·입력 제한·분석 제어·상태 단계는 이 같은 상태를 따른다. 해석 조회 실패가 최신 상세의 운영 상태를 막지 않는다.

조회는 진행 중 2초, 종료 후 10초다. 실행 기록은 `since` 커서로 중복 없이 합친다. 응답이 끝난 뒤 다음 조회를 예약하므로 요청이 겹치지 않으며, 경로 변경 시 중단한다. 흐름 변환·근거 묶음은 메모한다. 근거 이동과 대화의 자동 스크롤은 사용자의 선택·전송 때만 실행한다.

## 운영자 지시와 확인 경계

분석 중 입력은 기존 메시지 API를 사용한다. 종료된 장애는 지시 생성 API를 사용하고, 전송 중 종료되어 메시지 API가 409를 반환해도 동일 입력으로 지시를 만든다.

지시 상태별 화면:

- 계획 수립 중: 진행 표시와 취소.
- 실행 확인 대기: 한글 계획, 작업 종류·대상·수량, 사전 검사 결과와 경로별 변경 전→후, 영향 대상, 재시작, 서비스 중단 가능성, 원복 가능 여부와 방법, 경고를 전부 표시한다. 클러스터 범위 변경은 별도 적색 경고다.
- 확인 문구는 **정말 진행하시겠습니까?**, 버튼은 **진행 / 취소**다. 모든 작업의 사전 검사 통과, 부작용 설명, 계획 해시가 없으면 진행할 수 없다. 확인에는 표시된 계획 해시를 보낸다. 해시 충돌은 성공으로 표시하지 않는다.
- 비밀값 입력 대기: `secret_update.keys`별 비밀번호 입력, 자동 완성 끔, 값의 비저장·AI 비전달 안내. 값은 React 상태·대화·웹 저장소·로그에 넣지 않는다. 전송 전에 입력 DOM을 즉시 초기화하고 실패 시에도 값을 재표시하지 않는다. 응답은 상태와 키만 받는다.
- 실행 중 / 완료 / 실패 / 거절 / 취소 / 원복 중 / 원복 완료는 각각 한글 상태로 표시한다. 완료에는 결과와 검증 원문을 구분하고 원복 가능할 때만 확인 대화 후 원복 요청을 보낸다.

모든 쓰기는 기존 `request()`를 통해 `X-LiveProbe-Client: dashboard`를 보낸다. 이 화면의 확인은 서버 측 권한·계획 해시·사전 검사·부작용 검증을 대신하지 않는다.

## 접근성과 동작

- 인터랙션은 실제 버튼·링크·입력·선택 상자다. 한국어 접근 이름과 보이는 포커스를 제공한다.
- 필터·화면 전환·보조 탭·자원·단계 선택은 `aria-pressed`, 알림 버튼은 `aria-expanded`, 비동기 상태는 `role=status`, 오류와 클러스터 전체 영향은 `role=alert`다.
- 움직임 감소 설정에서는 핀 맥동·흐름 선·진행 표시 애니메이션을 끈다.
- 웹 폰트, 차트 라이브러리, 새 실행 의존성은 0개다. 운영 관제와 관제실은 지연 로딩한다.
- 모델 설정의 초안 유지, 버전 충돌, 저장, 기본값 복원과 검토 기록 경로를 유지한다.

## 로컬 검증

`e2e/README.md`에 표본 출처·한계·실행 명령을 기록한다. 단위 시험은 필터·인용 연결·근거 묶음·세로 흐름 배치와 연결면·지도 숨김·네임스페이스 압축 배치·미관측 합계·장애 핀·서비스 보존·명령 상태와 확인 차단을 검증한다. Playwright는 375/768/1440px에서 화면과 측면 영역의 `scrollWidth`/`clientWidth`, 버튼 사각형 겹침, 한국어 컨트롤 잘림, 키보드 진입, 알림 드롭다운, 확인·취소·원복·비밀값·전송 경합을 확인한다. 1440×900·1280×800에서는 운영 관제의 페이지 무스크롤·지도 점유율(55% 이상)·전체 자원 표시, 1440×900에서는 관제실의 페이지 무스크롤·흐름 전체 표시·대화 입력 노출을 확인한다.

모의 API 캡처는 `e2e/artifacts/mock/`, 실배포 읽기 전용 캡처는 `e2e/artifacts/live/`에 나누어 저장한다(같은 이름으로 덮어쓰지 않는다). 배치 검사는 연결선 문구가 자원 카드에 가려지는지도 측정한다. 자동 측정과 직접 이미지 검토를 구분한다. 이 로컬 검증은 실제 배포·실제 클러스터 복구·서버 비밀값 비저장 검증을 의미하지 않는다.
