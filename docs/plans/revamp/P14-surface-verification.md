# P14 실제 화면 검증 기록

## 대상과 범위

- 대상: 현재 작업 트리의 `/settings` 그룹 모델 편집과 `/incidents/987` 판단·근거 패널.
- 실행 주소: `http://127.0.0.1:5182`. 모델 설정 API는 별도 FastAPI 서버와 전용 PostgreSQL `lptest_p14_ui`에 연결했다. 다른 화면 데이터는 기존 클러스터에서 읽기만 수행했다.
- 운영 모델 배치 변경·장애 주입·LLM 호출은 이번 화면 검사에서 하지 않았다.
- 소스 해시, 관측 시각, 화면 크기, 키보드 이동, 콘솔·네트워크 검사는 `.e2e-tmp/revamp-p14/ui/surface-verification.json`에 저장했다. 이 문서는 배포 완료 증거가 아니다.

## 직접 관측한 상호작용

1. 데스크톱에서 SIMPLE 주 모델을 `라우터 자동 선택`에서 `직접 지정`으로 전환하고 모델을 `gpt-6.1-sol`로 바꿨다. 변경 2건 표시 → 저장 버전 1 성공 → API 재조회 → 페이지 새로고침 후 같은 배치를 확인했다. 모의 API가 아닌 별도 DB에 실제 저장했다.
2. 375px에서 NORMAL 로그 요약 추론을 medium으로 바꿨다. COMPLEX로 이동했다 NORMAL로 돌아와도 초안이 유지됐다.
3. 기본값을 초안에 불러온 뒤 저장 버전 2로 복원했다. API를 다시 읽어 `groups == defaults.groups`, `router == defaults.router`임을 검증했다.
4. 실제 사건 #987에서 `판단·근거`를 열고 후보 점수와 Workflow 기록을 확인했다. 375px 문맥 패널 clientWidth/scrollWidth가 모두 319px이고, 페이지 폭도 375px로 가로 넘침이 없었다.
5. 실제 API에 연결한 별도 Playwright 검사에서 1440/768/375px의 모델 선택 컨트롤이 모두 화면 안에 있고 높이 36px 이상임을 확인했다. 사건 분류 모델에 포커스한 뒤 Tab으로 사건 분류 추론 강도로 이동하는 것을 확인했다.

## 발견·수정·재검증

| 관측 문제 | 심각도 | 수정 | 검증 |
|---|---|---|---|
| 모바일 주 메뉴 이름이 숨겨져 빈 이동 항목으로 보임 | 높음 | 메시/지도/사건/검토/설정 약칭과 전체 aria-label 제공 | 실패 테스트 재현 후 통과, 375px 재캡처 |
| DB JSONB가 키 순서를 바꿔 역할 행 순서가 저장 전후 달라짐 | 보통 | 그룹별 역할 순서를 명시적으로 고정 | 정렬된 JSON 응답 회귀 테스트 실패→통과, 768px 재캡처 |
| 375px 후보표에서 선택 배지가 `선`/`택` 두 줄로 분리됨 | 보통 | 한 줄 배지를 모델 ID 아래 배치하고 글자 크기 14px 적용 | Range 행 수 2→1, 실제 사건 재캡처 |

검토한 화면에서 한글 잘림, 겹침, 가로 넘침이나 사용할 수 없는 컨트롤은 재관측되지 않았다. 전체 제품 접근성 인증이나 모든 브라우저·상태에 대한 포괄 통과를 뜻하지 않는다.

## 자동 검사

- 실제 UI+전용 DB 점검: 캡처 3개, 기본값 복원 확인. pageerror 0, console error 0, HTTP 4xx/5xx 0, 비정상 실패 요청 0. 화면 전환에 따른 취소 요청(net::ERR_ABORTED)은 검사에서 구분했다.
- Playwright: 24 passed (9.6s). 모델 편집 동작 검사는 모의 API, 사건 패널 검사는 실제 사건 데이터를 사용하므로 두 종류를 구분한다. 사건 3개 폭 검사는 프로젝트별 반복 실행을 포함한다.
- 프런트 단위 테스트: 29 passed, skipped 0.
- `npm run build`: 성공. 512KB 청크 크기 권고 경고는 남아 있으며 오류는 아니다.

## 정리

- 시험 Vite 서버 5181/5182와 FastAPI 서버 8001을 종료했다. 종료 후 세 포트가 모두 비활성임을 소켓 검사로 확인했다.
- surface-verification.json의 모든 소스 해시가 최종 작업 파일과 같고, 기록한 최종 캡처 3개가 존재함을 재확인했다.
- lptest_p14_ui 데이터베이스는 기본값으로 복원한 버전 2 상태로 보존한다. 운영 DB/모델 설정은 바꾸지 않았다.

## 당시 남은 검증

- API/화면 클러스터 배포 후 동일 동작 재확인.
- B1~B3/B5 작업 통합 및 전체 회귀 테스트, 실제 새 사건의 설정 revision/역할 적용 확인.
- 독립 코드 검토와 전체 P14 완료 판단은 별도다.

## 최종 배포 화면 재확인

- 최종 주소: `http://liveprobe.localhost`. API/대시보드 digest와 소스 일치는 `.e2e-tmp/revamp-p14/release-readback.json`에 기록했다.
- 실제 운영 UI에서 고위험 그룹을 직접 지정 astra/high로 저장(버전 3), 새로고침 보존, 실제 #990의 evidence_curator astra/high 및 safety_verifier astra/xhigh 성공을 확인했다. 이후 UI에서 원래 배치를 버전 4로 복원하고 API를 다시 읽었다. #990의 실행 배치는 버전 3으로 유지된다.
- 실제 #990 판단·근거의 문맥 패널 clientWidth/scrollWidth: 1440px에서 379/379, 768px에서 712/712, 375px에서 319/319. 작은 화면의 분석 대화↔판단·근거 전환과 키보드 Tab 이동을 확인했다.
- 375/768/1440px 설정 및 #990 화면, 768px 선택 지도 상세의 최종 캡처 7개와 소스 해시·오류 기록: `.e2e-tmp/revamp-p14/live-ui/final-readonly-receipt.json`. pageerror/console/HTTP 오류 0. 이미지를 직접 읽어 한글/모델 선택 컨트롤의 겹침과 가로 잘림이 없는지 확인했다. 긴 Workflow 식별자는 좁은 폭에서 줄바꿈된다.
- 전체 브라우저 검사는 처음 73개 통과·768px 지도 상세 2개 실패였다. 600px 이하에서만 상세가 다시 보이는 기존 CSS 구멍을 1100px 이하 bottom drawer로 고쳐 같은 전체 검사를 다시 실행했다: **75 passed (25.9s)**. 모델 편집 예외/충돌 검사는 모의 API이며 실제 영속화 검사는 위 실제 UI/DB 실행으로 분리한다.
- 프런트 단위 29개, tsc/Vite build 통과. 약 512KB 청크 권고 경고는 남는다. 자동 검사나 캡처 확인을 제품 전체 접근성 인증으로 부르지 않는다.

## 제공 화면 추가 게이트

- 실제 `http://liveprobe.localhost/settings`를 별도 브라우저 세션에서 1440×1000, 375×900으로 열었다. 그룹 선택과 하단 저장/기본값/다시 불러오기 버튼을 스크롤해서 직접 확인했다. 변경 0건에서는 저장 버튼이 비활성인 정상 상태다.
- 데스크톱에서 안전 검증 모델에 포커스한 뒤 실제 Tab 키 입력으로 안전 검증 추론 강도로 이동했다. 모바일에서는 포인터로 다시 불러오기를 눌러 저장 버전 4가 유지됨을 확인했다. 설정 저장 요청은 하지 않았다.
- 모바일 버튼 좌표: 저장 left/right 72/178.17, 기본값 186.17/300.66, 다시 불러오기 72/230.36. 버튼은 두 줄로 배치되며 겹치거나 화면 밖으로 나가지 않았다. 페이지 client/scroll 폭 375/375.
- 같은 브라우저에서 실제 `/incidents/990`의 판단·근거를 포인터로 열고 분석 대화로 복귀했다. 페이지 375/375, 문맥 패널 304/304로 가로 넘침 없음. 이 브라우저는 고전 스크롤바 공간을 사용하므로 기존 headless 319/319 측정과 구분한다.
