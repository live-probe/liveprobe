## 남은 범위 차이와 미수행

- 인터뷰의 “Secret 외 전체 자원 변경”은 달성하지 않았다. 우회 방어를 위해 PV/PVC/StorageClass·임의 CR·RBAC/admission·Namespace 쓰기·보호 namespace 변경 등을 차단한다. 기존 워크로드 변경은 scale·CPU/메모리·restart 등에 한정한다. 제한 구현본을 전체 범위 지원으로 표현하지 않는다.
- 운영자 명령 검증은 Kubernetes 구성/API 반영 확인이며 서비스 건강·rollout 완료의 전면 검증이 아니다. Secret은 쓰기 수락만 확인하고 값은 읽지 않으며 이전 값 원복도 지원하지 않는다.
- 진행 중 `cluster_change`의 실제 백엔드 응답부터 화면까지 연결한 통합 브라우저 시험은 수행하지 않았다. 백엔드 HTTP 분리 회귀와 모의 화면 시험은 수행했다.
- W18 전체를 마지막 p15h API에서 다시 실행하지 않았다. 8개는 p15e, 마지막 2개는 p15f에서 완결한 관측이다. 실패·미완결을 지우거나 다른 사례로 바꾸지 않았다.
- 앞선 W18 일부 캡처는 같은 파일명으로 덮어써졌다. 사건 #1002·#1004와 시도 이력은 보존한다. 최신 화면 캡처는 모의/실배포 디렉터리를 분리한다.
- 사람의 직접 시연은 사용자 요청 때 수행한다. 자동 시험을 사람의 사용성 검증이라고 부르지 않는다.
- DB 백업의 목록 검사는 했지만 실제 복원은 실행하지 않았다. 원격 CI·외부 공개·push도 하지 않았다.

기본 Dockerfile의 Node 기반 이미지 다운로드가 지연되어 p15p 빌드가 시간 초과했다. 성공한 클린 이미지 빌드로 기록하지 않는다. 의존성 manifest·lock 변경 없이 로컬 기존 의존성으로 형 검사·빌드·시험한 dist를 재사용한다. `scripts/build-dashboard-assets.py`가 p15o의 정확한 로컬 nginx 런타임을 실행 없이 export하고 이전 html만 제외한 rootfs를 만든 뒤, `dashboard/Dockerfile.assets`에서 이 rootfs와 새 dist로 네트워크 없는 이미지를 만든다. 로컬 digest FROM의 원격 registry 해석 실패와 stdin tar 경로 오류는 실패 이력으로 남겼다. 최종 로컬 폴더 context 빌드는 성공했다. 최종 도구 버전으로 별도 p15p-repro도 실제 재빌드했고 배포 이미지와 정적 파일 7개 해시가 같음을 확인했다. 재빌드 이미지로 운영 Deployment를 바꾸지는 않았다. 최종 이미지·번들 일치·실배포 검증은 별도 확인하며, 이 대체 경로는 외부 기반 이미지까지 다시 받은 클린 빌드 증거를 대신하지 않는다.
