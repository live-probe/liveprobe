상태: 권장안 확정 → 독립 검토 지적 및 후속 경계 수정 → 마지막 한정 재검토 통과 → 화면 p15p-local 배포(2026-10-22). 아래 관측과 최종 판정은 P15-final-verification.md·현재 소스 manifest를 따른다.

## 사용자 지시로 확정된 기준

- 운영 관제의 주인공은 서비스 연결 지도다. 큰 지도를 첫 화면에서 전체적으로 볼 수 있어야 한다.
- 별도 운영 관제 제목·소개 헤더와 큰 노드·Pod 요약 카드는 제거한다. 보조 상태 정보는 지도 옆 사이드 영역으로 옮긴다.
- 진행 중 장애는 우측 상단 알림 버튼을 눌렀을 때 아래로 펼쳐지는 목록으로 제공한다. 고정된 큰 장애 목록으로 지도 영역을 차지하지 않는다.
- 장애 관제는 한글 요약·해석을 먼저 보여 주고, 해당 항목을 선택하거나 펼칠 때 영어 원문을 확인한다. 원문 자체를 바꾸거나 버리지 않는다.
- AI 분석 흐름은 가로가 아닌 세로 진행으로 바꾼다.
- 의미 없는 페이지 내부 스크롤과 중첩 스크롤을 줄인다. 꼭 필요한 스크롤은 어떤 작업을 위한 것인지 설명할 수 있어야 한다.
- 상세 배치는 위 기준을 충족하는 방향으로 제안한다. 기존 배치를 전제로 한 시각 검증 통과를 새 요구 충족으로 간주하지 않는다.

## 실제 화면·저장소 확인

- 최초 계획서 `과제계획서.md`를 전체 읽었다. 운영자·SRE의 장애 대응, 라우터의 수준 판단, 그룹·역할별 분석과 사람 개입이 제품 목적이다. 초안의 과거 모델명·범위를 새 요구로 재승인하지 않는다.
- 인터뷰 시점 기반 HEAD `efcd0a3`. 백엔드는 커밋됐고 화면·기록 변경은 미커밋이었다. 구현은 아래 권장안 확정 이후에 진행했다.

## 수락 기준

1. 1440×900, 1280×800에서 운영 관제 `.main`의 세로 스크롤이 없고, 지도 캔버스가 화면 면적의 55% 이상이며 상단에서 120px 안에 시작한다.
2. 알림 버튼이 진행 중 장애 수를 표시하고, 드롭다운에서 장애를 선택하면 관제실로 이동한다. Esc 키와 바깥 클릭으로 닫힌다.
3. 지도의 장애 핀을 누르면 관제실로 이동하고, 정상 자원을 누르면 보조 영역에 자원 상세(Service 이름·포트·엔드포인트, 원문 펼치기)가 열린다.
4. 1440×900 관제실에서 페이지 스크롤이 없고, 모든 흐름 노드가 캔버스 안에 보이며, `depth`가 큰 노드일수록 아래에 있다.
5. 근거 묶음에서 한글 해석이 먼저 보이고 원문은 접혀 있다. 펼친 원문은 API 원문과 문자열이 같다.
6. 기존 기능 회귀 없음: 지시 확인·취소·원복·Secret 입력·steering·일시정지 시험, 375/768/1440 겹침·잘림 시험을 통과한다.
7. 실제 배포본에서 같은 구조를 캡처로 직접 확인한다.
