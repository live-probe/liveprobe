## 3. 참고자료가 실제로 쓰였는가

LiveProbe DB의 citation 기록 기준으로, 참고자료(`reference_guide`) 청크가 검색 결과에 들어간 사건은 **사용 쪽 12건 중 3건**(N3-01, N3-02, N3-03)이었다. 나머지 9건은 런북과 공개 문서가 우선 검색돼 참고자료가 상위 3개에 들지 못했다(RAG `k=3`).

## 4. 해석 (새 사례 12개에서의 관찰)

- **참고자료가 판단을 개선했다는 근거는 없다.** 차이는 1건이고, 그 1건도 두 실행에서 수집된 지표가 달랐던 것이 원인이다.
- 참고자료가 검색된 사건이 3건뿐이라, 지금 구조에서는 영향이 제한적이다. 영향을 보려면 검색 상위 개수(k)를 늘리거나, 참고자료를 유형별로 1개씩 항상 포함하는 방식이 필요하다(미검증).
- 참고자료의 규칙(항목 4)은 근거가 엇갈릴 때 보수적인 쪽(인계)으로 이끌었다. 안전 측면에서는 의도한 방향이다.
- 정책 C 자체는 새 사례에서도 동작했다. OOM 3건 중 2~3건, 이미지 문제 1건, 풀 점유 1건이 자동 복구됐다. 엔드포인트 손실 3건은 모두 정확히 인계됐다.

## 5. 실행 중 발견한 버그

- 정책 C에서 별도 쓰기 계정을 붙인 뒤, `rollout_undo`도 그 클라이언트로 보내져 `AttributeError: request_rollback`으로 실패했다(N1-03 본 실행, 두 방식 모두).
- 롤백은 롤백 컨트롤러 경로, 타입 조치 5종만 쓰기 계정을 쓰도록 분리했다(`Engine._kube_for`, 회귀 테스트 추가). 재실행에서 두 방식 모두 롤백 성공을 확인했다.
- 정책 C 88쌍에는 롤백 조치가 없어 영향이 없었다. 10-07 이후 이 버그가 있던 기간에 실제 운영 사건의 롤백이 필요했다면 실패했을 수 있다.
