# LiveProbe 관제 개편 요구사항 인터뷰

## 상태

요구사항 확인 중. 구현·배포·장애 주입·실제 AI 호출은 승인되지 않았으며 이 문서는 계획용 기록이다.

## 요청에서 명시된 방향

- 사용자 로그인 제거. 노출 범위와 조치 승인 경계는 별도 확인 필요.
- 밝고 단정한 통합관제 디자인. ChatGPT 라이트 모드를 시각적 참고로 삼는다.
- 첫 화면에 클러스터 자원 지도와 실제 관측 데이터 기반 통신 흐름을 표시한다. 필요한 수집 계층이 없으면 구축 범위에 포함한다.
- 이상 알림, 영향 자원의 경고 표시, 사건 상세 및 AI 대응 진행 화면을 연결한다.
- 제품 LangGraph 에이전트는 Codex CLI만 사용한다. 사용 가능한 계정은 두 개이며 배분 정책은 미확정이다. Claude는 Hermes 오케스트레이션용으로 분리한다.
- 개편 완료 후 60개 사건 × 4가지 방식의 실제 평가를 수행하고 과제계획서가 요구하는 결과와 향후 판단용 참고자료를 만든다. 지금은 평가 실행하지 않는다.

## 확정된 요구사항

### 관측 범위

클러스터 전체를 대상으로 한다. 시스템·관측 도구를 포함한 전체 자원과 실제 통신을 수집 대상으로 삼으며, 네임스페이스 간 통신·외부 연결·실패 및 차단된 연결을 포함한다.

이는 수집 범위의 결정이며 전체 트래픽이 현재 관측 가능하다는 증거가 아니다. 수집 방식, 관측 사각지대, 지원 프로토콜, 필요한 권한, 자원 사용량은 저장소와 실행 환경을 조사하여 계획에 명시해야 한다. 구성 관계와 실제 관측된 통신은 구분하고 미관측을 정상 또는 무통신으로 처리하지 않는다. 전체 관측은 전체 변경 권한을 뜻하지 않는다.

### 접근 및 인증

로컬 컴퓨터에서만 접근하는 PoC로 한정한다. 설치 후 로그인 없이 바로 대시보드에 진입하고 조회·설정·허용된 조치 승인을 사용한다. 사용자 인증은 현재 범위에서 제거하며, 향후 사용자가 요청할 때 별도 도입한다. 외부·사내망 공동 접근은 현재 범위에 포함하지 않는다. 로컬 접근 제한은 UI 안내만이 아니라 실제 배포 노출 경로에서도 검증해야 한다.

사용자 인증 제거는 Kubernetes RBAC, 서비스 간 인증, Secret 보호, 승인 네임스페이스 제한, 금지 대상 변경 차단을 제거하는 요구가 아니다. 조치의 자동 실행 범위는 다음 질문에서 확인한다.

### 자동 대응과 운영자 개입

감지 즉시 자동 분석을 시작하고, 운영자가 개입하지 않아도 분석·조치·검증을 계속하는 흐름을 기본으로 한다. 사용자는 이번 PoC에서 고위험으로 분류된 작업도 실행 대상으로 포함하기를 요청했다. 위험 분류만으로 일괄 중단하는 대신, 운영자 검토가 필요하다고 판단한 작업의 근거와 실행 결과를 별도 기록하여 향후 사용자가 기준을 정할 자료로 제공한다.

고위험 실행의 계획 범위는 재생성 가능한 전용 PoC 클러스터의 기반 구성까지 포함한다. 지정 시험 서비스·DB, LiveProbe·관측 시스템 설정 및 재시작에 더해 Node 재시작·drain, 클러스터 범위 RBAC와 네트워크 기반 구성 변경을 시험 대상으로 포함한다. 대시보드·클러스터와 독립된 실행 기록 및 외부 복구 경로를 전제로 한다. 영구 데이터 삭제와 자격증명 노출은 제외한다. Secret 변경, 임의 Control Plane 변경, 자유형 명령 실행을 포괄 승인한 것으로 해석하지 않는다. 기존 과제계획서의 고위험 이관 정책 및 보호 대상 제한과 달라지므로 문서·실행 정책·평가 기대 대응을 일관되게 수정하는 계획이 필요하다. 현재 인터뷰는 실제 조치 실행 승인이 아니다.

AI 작업 화면은 ChatGPT와 같은 대화형 진행 피드를 제공한다. 관측 근거, 수행 중인 단계와 도구 작업, 판단 요약, 조치 및 검증 결과를 표시하고, 운영자는 실행 도중 메시지로 방향을 조정할 수 있다. 비공개 내부 사고 과정을 노출하는 요구로 해석하지 않는다. 개입 없이 관찰만 해도 흐름이 계속되어야 한다. 메시지 반영 시점, 실행 중 조치 중단·일시정지 의미는 미확정이다.

### Codex 계정 운영

두 계정은 주 계정·예비 계정으로 운영한다. 기본은 주 계정으로 실행하고 사용 한도에 도달하면 예비 계정으로 이어간다. 두 계정 모두 사용할 수 없으면 진행 상태와 기록을 저장하고 대기하며 API·Claude로 전환하지 않는다. 인증 정보와 CLI 실행 환경은 계정별로 격리하고, 계정 전환 시 중복 조치를 실행하지 않도록 실행 상태를 확인한다. 정확한 재개 단위와 지원 모델·추론 강도는 구현 전 확인하여 고정한다.

## 확인 기록

- 질문 1: 첫 화면에서 자원과 실제 네트워크 통신을 어디까지 보여줄 것인가? 답변: 선택지 2 — 시스템·관측 도구를 포함한 클러스터 전체 자원과 실제 통신, 네임스페이스 간 통신·외부 연결·실패 및 차단된 연결을 수집 대상으로 한다.

- 질문 2: 로그인 제거 후 접근 범위와 조치 권한은? 답변: 로컬 컴퓨터에서만 접근하며 설치 후 바로 사용한다. PoC에는 사용자 인증이 필요 없으며 사용자가 추후 요청할 때 도입한다. 조회·설정·허용된 조치 승인은 로그인 없이 사용하고 기존 클러스터 안전 제한은 유지한다.

- 질문 3: 장애 감지 후 AI가 자동으로 어디까지 진행할 것인가? 답변: 자동 분석·복구를 기본으로 고위험 작업도 PoC 실행 대상에 포함하고, 운영자 검토 필요 작업은 별도 기록한다. 대화형 화면에서 AI 작업을 관찰하고 실행 중 메시지로 방향을 조정할 수 있어야 하며, 개입 없이도 계속 진행한다. 고위험 작업의 구체적 허용 경계는 미확정이다.

- 질문 4: 고위험 자동 실행의 대상 경계는? 답변: 선택지 3 — 재생성 가능한 격리 PoC 클러스터에서 시험 서비스·DB·LiveProbe·관측 시스템 및 Node 재시작·drain·클러스터 RBAC·네트워크 기반 변경까지 포함한다. 독립 실행 기록과 외부 복구 경로를 전제로 하고 영구 데이터 삭제·자격증명 노출은 제외한다.

- 질문 5: 두 Codex 계정의 운영 방식은? 답변: 선택지 1 — 주 계정으로 실행하고 사용 한도 도달 시 예비 계정으로 전환한다. 둘 다 사용할 수 없으면 기록을 저장하고 대기하며 API·Claude로 전환하지 않는다.

- 질문 6: 참고자료의 판단 지원 효과를 어떻게 검증할 것인가? 답변: 선택지 1 — 240개 비교 평가를 먼저 완료하고 참고자료를 만든 다음 별도의 새로운 장애 사례로 검증한다. 사용자는 향후 시연용 새 사례도 추가할 예정이다. 새 사례 정답은 참고자료와 에이전트 입력에 포함하지 않는다.

## 인터뷰 종료 및 계획 경계

여섯 질문의 답변을 받아 인터뷰를 종료한다. 목표와 핵심 운영 경계 및 평가 순서는 확정되었으나, 아래 기술·수치 세부사항은 확정된 요구가 아니다. 상세 계획에서 제안값과 구현 전 확인 조건으로 구분한다. 계획 승인은 구현·배포·실제 AI 호출·장애 주입의 실행 승인을 뜻하지 않는다.

## 미결 사항

- 허용 조치별 구체적 파라미터·원복 및 중단 조건, 기존 과제계획서와 평가 정답표의 정합성은 계획 단계에서 명시해야 한다.
- 운영자 메시지 반영 시점과 일시정지·중단 동작.
- Codex 두 계정의 격리·배분·사용 한도 처리와 비교 방식별 모델·추론 강도.
- 지도 정보 수준, 알림 전달 범위, 관측 신선도 및 장애 시 표시 기준.
- 평가 자료의 검색·참조 방식과 평가 정답 유출 방지 및 데이터 분리.
- 완료 검증과 디자인 승인 기준.
